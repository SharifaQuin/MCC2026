# MCC Training Portal

A bilingual (English/Spanish) employee training and onboarding portal for **Mama's Cleaning Crew**, built with Next.js and PostgreSQL, deployed on Railway.

## What's included

- Trainee flow: language selection, sequential module unlock, lessons with an optional video field, end-of-module quizzes requiring a 100% passing score (with retakes).
- Admin dashboard: employee list with completion at a glance, drill-into-employee results, a bilingual content editor for modules/lessons/quizzes, and an invite-employee flow.
- Trainer/Field Supervisor role: read-only access to employee progress and results (no content editing).
- All 25 training modules migrated from `mcc_training_builder.jsx`, including the full Spanish translation.

## Tech stack

- **Next.js 14** (App Router, Server Actions) — TypeScript
- **PostgreSQL** via Prisma ORM
- **Auth**: email + password, admin-issued invite links, httpOnly JWT session cookie (no email-sending infrastructure required)
- **Hosting**: Railway

## First-time Railway setup (step by step)

If you've never used Railway before, follow these steps in order.

### 1. Create your Railway account

Go to [railway.app](https://railway.app) and sign up (GitHub login is easiest since this project lives in a GitHub repo).

### 2. Create a new project from this repo

- From the Railway dashboard, click **New Project → Deploy from GitHub repo**.
- Select this repository. Railway will detect it as a Node.js/Next.js app automatically (via Nixpacks) and start a first build — it will fail until you add the database and environment variables below, and that's expected.

### 3. Add a PostgreSQL database

- In your Railway project, click **+ New → Database → Add PostgreSQL**.
- Railway provisions a Postgres instance and automatically creates a `DATABASE_URL` variable — but it's attached to the *database* service, not your *app* service yet.
- Click on your **app service** (not the database) → **Variables** tab → **New Variable → Add Reference** → select the Postgres service's `DATABASE_URL`. This links the two services so your app can reach the database.

### 4. Set the remaining environment variables

Still in your app service's **Variables** tab, add:

| Variable | Value |
|---|---|
| `AUTH_SECRET` | A long random string. Generate one locally with `openssl rand -base64 32`, or use any password generator. |
| `ADMIN_EMAIL` | The email for the first admin (owner) account, e.g. `shar@mamascleaningcrew.com`. |
| `ADMIN_NAME` | The admin's display name, e.g. `Shar`. |
| `ADMIN_PASSWORD` | A temporary password for the first admin login — **change it after your first login isn't built into v1, so pick something you're comfortable with for now and treat it carefully.** |
| `NEXT_PUBLIC_APP_URL` | Your Railway-provided public URL once you have one, e.g. `https://mcc-training.up.railway.app` (see step 6 — you can leave this blank initially and add it after your first deploy, then redeploy). |

You do **not** need to set `PORT` — Railway provides it automatically.

### 5. Deploy

- Trigger a redeploy (Railway usually does this automatically after you save variables — if not, click **Deploy** on your app service).
- On every deploy, the app automatically runs database migrations (`prisma migrate deploy`) and seeds the training content + your admin account (`prisma/seed.ts`) before starting the server. This is safe to run repeatedly — it skips anything that already exists.
- Watch the **Deployments** tab for build/runtime logs. A successful deploy will show the Next.js server starting and log lines like `Created admin account: ...` and `Seeded module: ...` on the very first run.

### 6. Get your public URL

- In your app service, go to **Settings → Networking → Generate Domain**. Railway gives you a free `*.up.railway.app` URL.
- Copy that URL into the `NEXT_PUBLIC_APP_URL` environment variable (step 4) and redeploy once, so invite links generated by the admin dashboard point to the right place.

### 7. Log in

- Visit your new URL, log in with the `ADMIN_EMAIL` / `ADMIN_PASSWORD` you set.
- From **Employees → Invite Employee**, create your first real employee account. The invite flow generates a one-time link — copy it and send it to the employee yourself (text, email, whatever's easiest); there's no automatic email sending in v1.

That's the whole setup. Future code changes just need a `git push` — Railway redeploys automatically if you connected it to your GitHub repo.

## Local development

```bash
npm install
cp .env.example .env      # fill in DATABASE_URL (a local Postgres) and AUTH_SECRET
npm run db:migrate:dev    # creates tables
npm run db:seed           # loads the 25 training modules + admin account
npm run dev
```

## Content & translation status

- All 25 modules' English content is migrated from `mcc_training_builder.jsx`.
- Spanish translations are complete for all 25 modules (translated to match the register/tone of the original "Who We Are" example — informal *tú* form, warm but professional). A few internal-system terms (e.g. "Dirt Code", "Lockout Fee") were translated with the English term kept parenthetically since staff use those exact terms daily — review these in the admin content editor and adjust if you'd prefer them left entirely in English.
- Video URLs for the hands-on cleaning modules (Bathroom, Kitchen, Living Area, Advanced Cleaning, Time Management) are empty placeholders — drop in YouTube embed links via the admin content editor once videos are ready; no code changes needed.
